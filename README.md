# Study Compass（コンテスト版）

「わからない」を越えて、自分の可能性へ。

短いチェックで「現在地」を知り、つまずきの原因を探して、今日やることを1つに絞る学習支援Webアプリのデモです。
今回は **中学2年・数学「一次関数」** だけをモデルケースとして収録しています。

**公開URL：https://megkawa1010.github.io/study-compass-contest/**

- ログイン不要・個人情報の入力なし
- HTML / CSS / JavaScript だけで動く（ビルド・サーバー処理・外部API なし）
- 記録はその端末のブラウザ（localStorage）にだけ保存

## AIの使用について（正直な現状）

このデモの診断は **ルールベース** です。
各問題に「確認するスキル」と「前提知識」を持たせ、基礎問題の結果から原因確認問題を選び、その結果の組み合わせでつまずき候補を推定しています。
**外部のAI（生成AI API）は、このデモでは使っていません。** 将来、結果文の生成や問題の自動作成にAIを使う想定の設計です。

## 画面の流れ

1. ホーム → 2. 初期設定（学年・教科・単元・学習状況）
3. コンパスチェック（基礎5問・1画面1問・ヒント/わからない付き）
4. 追加確認（**回答によって出す問題が変わる**。原因確認 C1〜C5 / 標準 S1・S2）
5. 現在地（ルートマップ・できているところ・もう少し確認したいところ・今越えたいところ・発見）
6. 今日の学習（25分・3ステップ。解説→練習→チェックで止まった問題に再挑戦）
7. 振り返り（😊🤔😣 → 記録・現在地の更新）

基礎・標準がすべてできた場合は、応用（料金プランの文章題 A1）を「Aの式 → Bの式 → 方程式と答え」の3ステップで学習します。

## 学習データ（Phase 1）

保存キー `study-compass/v2`（localStorage）に、次の形で持ちます。

- `answer_history[]` … 回答1件ごとの記録（上書きしない）
  `id, user_id, session_id, context(compass_check|lesson), question_id, unit, skill, level, correct, hint_used, unknown_selected, answered_at, self_evaluation`
- `sessions[]` … コンパスチェック1回分（出した問題・今日越えること・つまずき候補・その時点の確かさの控え・ふり返り）
- `skill_state{}` … スキルごとの現在地。**保存値を足し引きせず、毎回 answer_history 全体から計算し直す**
  `learning_status（未学習/学習中/要確認/理解/活用/定着）, basic/standard/application/retention（not_checked/pass/needs_review）, confidence, attempt_count, correct_count, suspected_root_causes, last_checked, next_action`
- `profile.school_progress` … 単元ごとの「習った / 習っている途中 / まだ習っていない」
- `user_id` は端末内で作る匿名ID（個人情報は持たない）

確かさ（confidence）の考え方（調整値は `js/engine.js` の `CONFIG`）

- 上限は「どのレベルまでできたか」で決まる：基礎 0.50 / 標準 0.65 / 応用 0.80、数日後もできたら +0.12（2回目で +0.15、最大 0.95）
- その中で、最近の結果を重めに見る（ヒントありの正解は半分、練習はチェックの半分の重さ）
- 1回の回答で下がるのは最大 0.15。最初に「できた」日から3日以上あとに自力でできたら「定着」
- レベルの判定は直近3回を新しいものほど重く見る（1回の×で取り消さない）
- まだ習っていない単元のスキルは、できなくても「要確認」ではなく「未学習」
- つまずき候補は、前提スキルをたどって一番根元の「まだ不安定なスキル」を挙げる

コンテスト版（v1）の記録は、初回に読み込んで履歴に移します（v1 のデータは消しません）。

## 問題バンク

全70問（既存12問＋追加58問）。一覧は `?debug=bank` で図・答え・解説つきで確認できます。

| スキル | 基礎 | 標準 | 応用 | 定着 | 計 |
|---|---|---|---|---|---|
| 変化量・式への代入・変化の割合・傾き切片・グラフ式（一次関数） | 3 | 3 | 2 | 2 | 各10 |
| 正負の数・文字式への代入・比例・座標（既習） | 3 | − | − | 2 | 各5 |

- 形式（format）：数式・表・グラフ・文章・数直線。一次関数の各スキルは3種類以上の形で出題
- 答えの種類（type）：number / linear / pair / choice / steps
- 応用問題（steps）は小問に分け、小問ごとに skill を持つ。`logic.analyzeSteps` で「どの小問で止まったか」と、そのスキルを原因候補として返す
- 定着用の問題（retention）は evidence_level（基礎相当・標準相当）を持つ。定着になるかは問題の種類でなく、最初にできた日から3日以上たってからの正解で決まる
- `SC.bank.pick(skill, level, { history, exclude, rng })` … 未出題を優先し、なければ一番前に解いた問題。同じ優先度からはランダム。`SC.bank.seeded(n)` で乱数を固定できる
- 既存の B1〜B5 / C1〜C5 / S1・S2 とコンパスチェックの流れは変更なし。バンクの問題を実際に出すのは Phase 2 から
- `tests/bank.test.js` で、必須項目・自分の答えで正解になるか・グラフの点が直線上にあるか・表が一次関数になっているか・定着問題が他と重なりすぎないか を機械的に確認

## 学習マップ：中1「一次方程式」

単元数を増やすより、単元どうしのつながりを地図として持つための拡張。スキルの定義は `js/engine.js` の `SKILLS`（`grade`・`unit`・`prerequisites`）、並び順は `SKILL_ORDER`／`ROOT_ORDER`。

| スキル | 前提 | 問題（基礎/標準/応用/定着） |
|---|---|---|
| 分配法則 distrib（既習） | 正負の数 | 3/0/0/1 |
| 方程式の意味 eqMeaning | 文字式への代入 | 3/0/0/1 |
| 等式の性質 eqProperty | 正負の数 | 3/0/0/1 |
| 移項 transpose | 正負の数・文字式への代入 | 4/4/0/2 |
| かっこのある方程式 eqParen | 分配法則・移項・正負の数 | 2/2/0/1 |
| 分数・小数の方程式 eqFraction | 等式の性質・移項 | 2/2/0/2 |
| 方程式の文章題 eqWord | 方程式の意味・文字式への代入・移項 | 1/2/2/1 |

- **問題**：39問。旧アプリ（study-compass-app）の一次方程式20問をすべて再利用（`source: "study-compass-app:linear-eq-XX"`）＋追加19問
- **一次関数とのつながり**：式への代入・グラフ・式 の前提に「移項」。方程式を解く必要がある一次関数の問題18問（`SOLVES_EQUATION`）だけが問題の前提に「移項」を持つ。y座標からxを求める・切片を求める問題など
- **原因さがし**：グラフ・式 × → 変化の割合 ○ → 座標 ○ → 移項 × → 正負の数 ○・文字式への代入 ○ → 戻る場所「移項」、のように1段ずつ一次方程式まで下りる
- **苦手と呼ばない**：記録のない一次方程式のスキルは「まだ（記録なし）」。未学習（not_learned）扱いは今の単元（既定は一次関数）だけ
- **子ども向けの表示**：戻る場所が一次方程式のスキルのとき、今日の学習に「一次関数の前に、方程式を少し確認しよう。」の1行だけ。履歴と保護者画面には「中1・一次方程式」のタグ
- **確認用**：`?debug=map` … 単元ごとのスキル・前提・この上に積むスキル・問題数・いまの状態、一次関数→一次方程式の道すじ、「移項」を前提に持つ問題、最近の原因さがしがどこまでさかのぼったか

## 学習マップ：中2「式の計算」

正負の数 → 文字式 → 式の計算 → … の1本の線ではなく、式の計算のスキルが一次方程式・連立方程式・一次関数の **それぞれ別の所** に前提としてつながる地図にした。

| スキル | 単元 | 前提 | 問題（基礎/標準/応用/定着） | この上に積むスキル |
|---|---|---|---|---|
| 同類項をまとめる likeTerms（新規） | 中1の土台 | 正負の数 | 4/0/0/3 | 移項・多項式の加法・減法・等式の変形 |
| 分配法則 distrib（既存を文字2つまで広げた） | 中1の土台 | 正負の数 | 5/0/0/2 | かっこのある方程式・係数をそろえる・かっこを含む式の計算 |
| 多項式の加法・減法 polyAddSub | 式の計算 | 同類項をまとめる・正負の数 | 6/2/0/5 | 加減法（主前提）・かっこを含む式の計算 |
| かっこを含む式の計算 polyMixed | 式の計算 | 分配法則・多項式の加法・減法 | 3/2/2/0 | かっこを含む連立方程式 |
| 単項式の乗法・除法 monoMulDiv | 式の計算 | 正負の数 | 2/2/1/0 | （まだなし。中3の展開へ） |
| 等式の変形 eqTransform（旧アプリになし） | 式の計算 | 等式の性質・移項・同類項をまとめる | 6/5/1/2 | 一次関数の「y = の形にする」問題・（あとで）代入法 |

- **問題**：旧アプリの式の計算18問をすべて再利用（`source: "study-compass-app:polynomial-calc-XX"`）。足したのは、等式の変形（8問）・同類項の定着（3問＋係数を見分ける基礎1問）・文字2つの分配法則（3問）・整理してから代入（2問）だけ
- **統合**：「式の値」は新しいスキルにせず、既存の「文字式への代入」を使う（整理してから代入は、小問1 かっこを含む式の計算 → 小問2 文字式への代入）。「文字2つの分配法則」も既存の「分配法則」。「単項式・多項式（項・係数）」は同類項をまとめるの基礎問題に含めた
- **同類項は中1の土台**：一次方程式（両辺に x がある問題）の前提なので、中2の単元に入れると「まだ習っていない」の影響で土台が抜けてしまう
- **加減法の階層**：加減法 → 多項式の加法・減法 → 正負の数。① 符号そのもの（正負の数まで戻る）② 項どうしの加減（多項式の加法・減法で止まる）③ 連立方程式特有の式全体の処理（前提はできていて、加減法そのもの）を分けられる
- **係数をそろえる側**：係数をそろえる → 分配法則 → 正負の数
- **答えの形 `poly`**：7x + 2y、−10xy、6x^2 などを入力できる（`SC.logic.parsePoly`）。項の順番・かけ算の順・x² と x^2 の書き方は同じ式とみなす。入力の補助ボタン（x・y・^2 など）つき
- **はじめてのチェック**：初期設定で「式の計算」を選ぶと、診断用の5問（多項式の加減2・かっこを含む式・単項式の乗法・等式の変形）
- **今日の学習のひとこと**：連立方程式や一次関数から式の計算へ戻るときは「連立方程式の前に、式の計算を少し確認しよう。」
- **多項式の加法・減法の補強**：加減法の原因さがしの入口なので、基礎6・定着5に。形を変えた（式から式をひく・かっこを外した途中の式を選ぶ・項の順番がばらばら・負の式をひく・A − B・小数）
- **等式の変形の補強**：基礎6（1回の操作だけ：両辺から式をひく・両辺をわる・どの操作をするか選ぶ）・標準5（文字が両辺・かっこ・x について解く）。かっこ → y の項を残す → 両辺をわる の小問で、計算（分配法則）／変形の理解（等式の変形）／等式の性質 を分けて記録。一次関数側に、y = の形に直してから答える問題（傾き・切片／グラフ・式／2直線の交点）を足し、前提に等式の変形を付けた。文字式の答えは y/2 + 2 の形も読む
- **定着用の問題を練習で使わない**：今日の学習の練習パートは、定着用（`usage: "retention"`）の問題を段階0では選ばない。練習で解いてしまうと、数日後の定着の確認に使えなくなるため
- **原因さがしの続きは翌日から**：追加4問の上限で確かめきれなかった前提は、次の日以降の定期チェックで P0（最優先）。同じ日にチェックを重ねない
- **10日分の試算**：`node scripts/simulate-days.js 10 30 式の計算`、原因を指定するなら `node scripts/simulate-days.js 10 30 連立方程式 polyAddSub`
- **確認用**：`?debug=map` の「式の計算 → 一次方程式／連立方程式／一次関数」

## 学習マップ：中2「連立方程式」と2直線の交点

一次方程式 → 連立方程式 → 一次関数 を1枚の地図にする拡張。単元ごとのスキルは `js/engine.js` の `UNITS`、初期設定で選べる単元は `SELECTABLE_UNITS`（連立方程式・一次関数）。

| スキル | 前提 | 問題（基礎/標準/応用/定着） |
|---|---|---|
| 連立方程式の意味 simMeaning | 方程式の意味・文字式への代入 | 3/3/0/3 |
| 係数をそろえる simCoef（式を何倍かする工程だけ） | 分配法則・等式の性質 | 3/1/0/3 |
| 加減法 simElim | 多項式の加法・減法（主前提）・係数をそろえる・移項 | 4/8/3/3 |
| 代入法 simSubst | 文字式への代入・かっこのある方程式・移項 | 2/2/1/3 |
| かっこを含む連立方程式 simParen | かっこを含む式の計算・加減法 | 2/1/0/3 |
| 小数・分数を含む連立方程式 simFraction | 分数・小数の方程式・加減法 | 2/1/0/3 |
| 連立方程式の文章題 simWord | 連立方程式の意味・方程式の文章題・加減法 | 3/2/2/3 |
| 2直線の交点 simGraph（単元は一次関数・連立方程式とのかけ橋） | 加減法・グラフ・式・座標 | 5/2/1/3 |

- **問題**：75問。旧アプリの連立方程式25問をすべて再利用（`source: "study-compass-app:simultaneous-eq-XX"`）＋追加50問（うち22問は、実際に不足が出たところの補強：2直線の交点の基礎・各スキルの定着・文章題の基礎・連立方程式の意味の標準）。定着は数字だけ変えた問題にならないよう、選ぶ・表・整理だけ・立式だけ・逆に求める、など形を変えた。式は `{` でくくって表示（図の種類 `system`）。検算用に `system`（ax + by = c の形）を持ち、`tests/bank.test.js` で答えが両方の式をみたすか確かめる
- **問題ごとの前提**：係数がそろっている加減法は「多項式の加法・減法・移項」だけ。式を何倍かする加減法は「係数をそろえる・多項式の加法・減法・移項」。だから、そろっている問題で「係数をそろえる」を確かめに行かない
- **途中の工程**：加減法・代入法・文章題・2直線の交点の一部は小問に分けた（例：引いた式 → y → x）。どの小問で止まったかで、符号ミス（加減法）／係数をそろえられない（係数をそろえる）／一次方程式にした後で解けない（等式の性質・移項）を分けて記録する
- **原因さがしの例**：加減法 × → 係数をそろえる ○ → 多項式の加法・減法 ○ → 移項 × → 正負の数 ○・文字式への代入 ○・同類項 ○ → 戻る場所「移項」。係数をそろえられない子は 加減法 × → 係数をそろえる × → 分配法則 × → 正負の数 ○
- **2直線の交点**：前提は 加減法（連立方程式側）と グラフ・式・座標（グラフ側）。連立方程式が記録上できていれば問題を出さずに○にして、グラフ側を確かめる
- **はじめてのチェック**：初期設定で「連立方程式」を選ぶと、診断用（`usage: "diagnosis"`）の5問でチェック（`SC.compass.unitCheck`）。まちがえたら、最初のチェックと同じ上限まで原因さがしの問題を足す。はじめて確かめたスキルは「前回より↑」と言わず「はじめて」と表示
- **学校の進み具合は単元ごと**（`profile.school_progress`、`profile.current_unit`）。「まだ習っていない」と答えた単元だけ未学習。答えていない単元は、記録がなければ「まだ（記録なし）」で、苦手とは扱わない。未学習のスキルは定期チェックの対象にしない
- **今日の学習**：学校の単元が連立方程式なら、連立方程式のスキルが「学校の単元」の候補。戻る場所を補強したら、最初にまちがえた問題のスキル（例：加減法）に戻る。前の単元まで戻るときの一言は「連立方程式の前に、一次方程式を少し確認しよう。」（一次関数から連立方程式へ戻るときは「一次関数の前に、連立方程式を少し確認しよう。」）
- **問題が足りないとき**：そのレベルの問題が1問もないスキルは、今日の学習でも定期チェックでも、そのレベルを目標にしない（例：移項に応用の問題はないので、定着で確かめる）。1問も出せなかった枠の時間は、いちばん大事な枠に回す（`?debug=plan` の記録に「問題不足」と出る）
- **テスト対策**：範囲を単元ごと（連立方程式・一次関数）に選べる。範囲チェックは上限6問で、仕上がりの低いスキル（△・？）から選ぶ
- **10日分の試算**：`node scripts/simulate-days.js 10 30 連立方程式`（3日ごとの定期チェックも含めて、再利用・緩和・出題できずを数える）
- **確認用**：`?debug=map` に「連立方程式 → 一次方程式」「一次関数 ⇄ 連立方程式（2直線の交点）」のつながりと、途中の工程を分けた問題の一覧

## 学校のようす（学校進度・学習範囲の管理）

学校で今どこをやっているか＋どこまで習ったか＋次のテストを、続けて更新できるようにした。**未学習 ≠ 苦手** を守るための土台。

- **入力はひとつ**：「一次関数は、学校ではどこまで進んだ？」で「変化の割合まで」のようにスキルを1つ選ぶだけ（「この単元はまだ始まっていない」も選べる）。前の単元は「習った」、後の単元は「まだ」に自動でそろえる
- **内部ではスキルごとに展開**：変化量・式への代入＝learned、変化の割合＝current、傾き・切片・グラフ式・2直線の交点＝not_learned（`E.expandUnit`・`E.schoolSkillStatus`）
- **保存**：`profile.school = { current_unit, units: { 単元: { status, current_skill, skills } }, next_test: { date, units }, updated_at, snooze_date }`。以前の `profile.current_unit`・`profile.school_progress` から自動で作り、同じ内容を書きもどす
- **学校でまだ習っていないスキル**：苦手判定しない（`not_learned`）・確かさを下げない・定期コンパスチェックに出さない・原因さがしで確かめない・単元のはじめてのチェックに出さない・保護者画面では「学校でこれから習う」
- **先取り**：今日の学習の候補は「習った＋学習中のスキル」と「次の1スキル」だけ。次の1スキルは種類「先取り」として分けて表示し（「まちがえても苦手にはなりません」）、まちがえたら「まだ習っていない内容に挑戦しました。今はできなくても大丈夫。」。回答に `preview: true` を付け、まちがいは理解度の計算に入れない（あとで学校で習っても数えない）。できた先取りはふつうに数える
- **ホーム**：小さなカード「学校のようす：一次関数・変化の割合まで／次のテストまで12日［更新する］」。`updated_at` から7日以上たったら「学校はどこまで進んだ？」［更新する］［今日はあとで］（強制しない）
- **テスト対策**：学校のようすで登録したテストの日・範囲を、テスト対策の初期値にする（変更できる）
- **保護者画面**：「学校の進度：「一次関数・変化の割合まで」　次のテストまで12日」
- **確認用**：`?debug=school` … current_unit・単元の status・current_skill・習った／学習中／まだのスキル・先取りできる次のスキル・テスト・今日の学習で学校枠に選ばれたスキル・除外した未学習スキル・先取りでまちがえた回数（計算に入れない）
- **今回やっていないこと**：つまずき補強と学校の学習を何分ずつにするかの調整（次の「今日の学習との連携強化」で）

## 問題バンクの合格基準（10日分の利用シミュレーション）

「各スキル5問」を目標にしない。スキルによって通る回数がまったくちがう（正負の数・等式の性質のようなハブは多く、あまり通らないスキルは少ない）ので、**10日程度使ったときに不自然な再利用が起きないか** で判定する。

```bash
node scripts/audit-bank.js 10
```

- **流すもの**：単元（一次関数・連立方程式・式の計算）× つまずきの原因（移項・多項式の加減・正負の数・等式の性質 など）× 30分／45分 × 学び方（補強したスキルだけできるようになる／学校の単元の練習でもできるようになる）の 28 本。3日ごとに定期チェックも行う
- **不自然な再利用**：① 今日の学習で、練習で出してから2日以内（`AVOID_LESSON_DAYS`）の問題をくり返した ② 定期チェックで、除外を「最近の問題」までゆるめないと出せなかった（段階2以降）③ 定期チェックで出題できなかった
- 前に解いてから日数をあけた再利用は「間をあけた復習」として数えるが、不合格にはしない
- スキルごとに「合格／要補強」と、どの問題・レベルでくり返したかを出す。足りなかったスキルだけを、足りなかったレベルに足す
- `tests/audit.test.js` で、fallback 0・今日の学習の不自然な再利用 3 以下・チェックで出題できないスキル 0 を守る
- 2026-10 の補強：不自然な再利用 273 → 1、今日の学習の再利用率 34% → 14%、チェックで出題できず 104 → 0（75問追加）

## 定期コンパスチェック（Phase 2）

1回の診断で決めつけず、記録を見ながら「今、確かめ直した方がよいスキル」を選んで、問題バンクから前回と違う問題を出す。調整値は `js/compass.js` の `CONFIG`。

- **発生条件**（どちらか）：そのスキルを最後にチェックしてから `COMPASS_CHECK_DAYS`＝3日 ／ 前回のチェック後に `COMPASS_CHECK_MIN_ATTEMPTS`＝5問練習
- **優先度**：1 確かさ 0.65 未満 → 2 標準・応用に要確認 → 3 一度できたが定着が未確認 → 4 定着していたが14日以上あいた → 5 直近4回で2回以上まちがい（最後も×）
- **問題数**：1回3〜5問、1スキル2問まで（優先度1・5のスキルに2問目）
- **出題レベル**：基礎が不安定→基礎／基礎OK→標準／標準OK→応用／応用OK→定着（既習スキルは基礎の次に定着）
- **除外**：直近3回のチェックで出た問題と、7日以内に解いた問題。定着を確かめる目的のときは、そのスキルで一度でも解いた問題を出さない。候補がないときだけ条件をゆるめ、その旨を記録する
- **ホーム**：条件を満たしたらお知らせ（今チェックする／今日はあとで）。起動時に強制しない。「今日はあとで」はその日のあいだだけ
- **結果**：スキルごとに前回→今回（◎○△）、上がったスキルは「ひとつ越えました！」、コメント、これまでの記録から見た現在地
- **今日の学習**：チェック後の skill_state から作り直す（前提に近い「まだ不安定」なスキルから。基礎が安定したら標準へ、標準もできたら応用へ）
- **マスター**：基礎・標準・応用・定着すべて pass ＋ 確かさ 0.85 以上。履歴から毎回計算するので、あとの不正解で下がりうる
- **応用問題の小問**：小問ごとに記録（`問題ID#s1`）し、どこで止まったかを残す。理解度の計算では「1問の中の同じスキルの小問」を1回分にまとめ、すべて正解のときだけ正解とする
- **保存**：`compass_check_history[]` … `id, session_id, date, questions, skills, skill_ids, reasons（問題ごとの選んだ理由）, before, after, comment, plan_key, focus_skill`
- **確認用**：`?debug=compass` … 対象スキル・理由・発生条件・出題候補（乱数の種1の例）・除外した問題・これまでのチェックの前後比較

## 確かさの動き方（1回の変化幅）

「一度の結果で決めつけない」ため、1回の回答で動く幅を小さく固定している（`js/engine.js` の `CONFIG.step`）。

- 定着の判定：数日後（最初にできた日から3日以上）の確認で、**ヒントなしで自力正解した日**だけを数える（同じ日は1日分）。「定着」の状態になるのは、その日数が2日以上 ＋ 直近3回のチェックに誤答がないとき。1回だけなら確かさは上がるが「定着」とは呼ばない（`retention_count` に日数）
- 定着用の問題ではヒントボタンに「（定着の確認は次回に）」と出す
- 正解：基礎 +0.04 ／ 標準 +0.05 ／ 応用 +0.06 ／ 数日後の確認（定着の証拠） +0.08
- 不正解：通常 −0.05 ／ 数日後の確認 −0.10 まで（それまでの正答率が高いほど下げ幅は小さい）
- 練習（lesson）はチェックの半分の幅、ヒントありの正解は上がる幅も半分
- 正解しても「到達レベルの上限」と「過去の正答率（新しいほど重い）」から決まる目標値より上には上がらない → 過去の履歴を考慮
- はじめは 0.30。何度も数日おきに確かめて、はじめて 0.85 以上（マスター）に届く

## 問題不足への対応

- 目安の問題数：基礎5・標準5・応用3・定着5（既習スキルは基礎5・定着5）。`?debug=bank` に「あと何問」
- 追加は `js/bank.js` に `add({...})` を足すだけ（索引・ランダム選択・テスト・一覧は自動で反映）。足りなくなったスキルから順に追加する
- 定期チェックで問題が足りないときは、除外条件を段階的にゆるめる：定着目的の「既出すべて除外」を外す → 直近2回・5日 → 前回のチェック・3日。どの段階でも「今回出した問題・前回のチェックの問題・3日以内の問題」は出さない
- ゆるめる前に、同じスキルの別レベルの未出題問題を使う
- `?debug=compass` の「問題不足」に、どのスキルでどの段階まで緩めたか・「問題不足のため再利用」を表示

## つまずき原因探索（Phase 4）

「この問題をまちがえた」で終わらず、「どの前提スキルまで戻ると理解できるか」をさがす。

- **道すじ**：まちがえた問題（応用問題なら止まった小問）のスキルから始め、その問題が持つ前提 → スキル地図の前提、の順に確かめる。前提の問題もまちがえたら1段さかのぼり、正解した前提が「ここまでは戻らなくてよい」境目になる
- **問題を出さずに済ませる**：同じチェックの中ですでに答えがわかっているスキル（「今回の答えから」）と、14日以内に確認して「できている」スキル（「記録から」）は、問題を出さずにその結果を使う
- **上限**：深さ3段・1スキルで確かめる前提3個・追加の問題は最初のチェック4問／定期チェック2問（`SC.rootcause.CONFIG`）
- **1段目の前提**：問題が `prerequisite_skills` を持っていれば、それだけを見る（地図の前提で補わない）。方程式を解かない問題で「移項」を確かめに行かないため
- **結論**：前提に原因がありそう／土台まで戻った／前提はできている（スキルそのものを練習）／別の問題ではできた（うっかりの可能性）／確かめきれていない。いずれも断定せず「〜の可能性があります」と伝える
- **最初のチェック**：C1〜C5 を最初の確認として使い、C もまちがえたら問題バンクからさらに前の前提を1問ずつ差し込む
- **定期チェック**：まちがえた問題があれば、その前提を確かめる問題を差し込む
- **今日の学習**：いちばん根元の「戻る場所」から始め、最後のステップは最初にまちがえた問題への再挑戦
- **続き**：確かめきれなかった前提は、次の定期チェックで最優先（P0「前回の原因さがしの続き」）
- **表示**：結果画面の「つまずきの道すじ」（例：変化の割合 × → 変化量 × → 正負の数 ○）。同じ場所にたどりついた道すじは説明を1回にまとめる
- **保存**：`explorations[]` … 症状・道すじ（どの問題で／記録から／今回の答えから）・結論・戻る場所・できている前提・次回に回す前提・判断の記録
- **スキル地図の変更**：傾き・切片 の前提に 変化の割合 を追加（傾き＝変化の割合）

### Phase 4 の微調整

- **確認済みスキルの追加問題は省略**：原因さがしの問題で正解した前提スキルに、同じチェック内で予定していた問題が残っていれば、原則として出さない。例外（確かさ0.3未満・過去の正答率が5割未満（3回以上）・ヒントありの正解・今回ほかでそのスキルを誤答）は予定どおり出す。省略した／残した理由は `compass_check_history[].skipped` と `?debug=compass` に記録
- **用途タグ `usage`**：diagnosis（B1〜S2）／practice／retention（定着用問題）／multi_use（追加問題の既定）。原因確認問題の説明文 `purpose` と名前がぶつかるため `usage` にした。`SC.bank.pick(..., { usage: [...] })` で絞れる

## 今日の学習の自動生成（Phase 5）

「現在地を知る → 目的地を決める → 今日の一歩を示す」の3つ目。固定プランを選ぶのではなく組み立てる（`js/planner.js`）。

- **入力**：school_progress（学年・教科・単元・「習った／途中／まだ」）、available_minutes（20/30/45/60・初期値を保存）、learning_goal（いつもの勉強／苦手を戻る／復習／もう少し先へ）、skill_state、原因さがしの結論（14日以内）、最近の学習履歴
- **優先順位**：P1 根本のつまずき（原因さがしの戻る場所＋いちばん根元の不安定なスキル）→ P2 学校で学習中の単元 → P3 定着の確認（一度できて3日以上）→ P4 得意の発展（標準・応用へ）
- **時間の枠**：20分＝ウォームアップ5／メイン10／確認5、30分＝ウォームアップ5／補強10／学校の単元10／確認5、45分＝5／15／15／発展10、60分＝復習10／補強20／学校の単元20／発展10。中身は skill_state で決め、当てはまらない枠の時間は大事な枠に回す
- **目標で入れかえ**：苦手を戻る＝学校の単元の5分を補強へ・発展も補強に／復習＝定着の確認と復習中心／もう少し先へ＝補強を発展に
- **学校の単元に戻る**：補強したスキルを前提にしている、まだ不安定な単元のスキル（例：変化量 → 変化の割合）に基礎から戻る
- **前進**：最近7日の練習で、そのレベルを2問以上・3問中2問以上できていれば、次は一つ上のレベル（または次のスキル）へ
- **問題**：練習向け（practice / multi_use / retention）を優先し、最近の診断・チェック（7日）と練習（2日）で出した問題を避ける。足りなければ段階的に緩めて再利用し、理由を記録
- **記録**：練習は `lesson`、「確認」のパートと定着の確認は `daily_check`（理解度のレベル判定に使う）。1問目の答えだけ記録。ふり返りは self_evaluation。プランと結果は `plans[]`
- **なぜ今日はこれ？**：できていること・迷っているところ・今日の流れを、子どもにわかる言葉で3〜4文
- **ホーム**：記録がある人は「今日の学習」が中心（今日越えること・時間・目標・はじめるボタン・なぜ今日はこれ？）
- **fallback**：自動生成でエラー、または出せる問題がないときは、固定10プラン（3ステップ）に切り替える。理由はプランに保存し `?debug=plan` に表示
- **確認用**：`?debug=plan` … 入力・skill_state・優先候補P1〜P4・除外したスキル・時間配分・選んだ問題と再利用の理由・生成の記録。時間・目標の切り替えと「日付を1日進める」ができる

## テスト対策モード（Phase 6）

日常学習と同じデータ（skill_state・answer_history）を使う。別のしくみは作らない（`js/testprep.js` ＋ `js/planner.js` のテストモード）。

- **入力**：テストの日・テスト範囲（一次関数の5スキルが既定。前の学年の内容も選べる）・1日の学習時間（今日の学習の設定と共通）。ホームの「テストの予定を入れる」から
- **仕上がり**：◎ 仕上がっている／○ 基本はできている／△ まだ不安定／？ まだ確かめていない（skill_state から）
- **残り日数の計画**：範囲に7日以上確かめていないスキルがあれば1日目は「テスト範囲チェック」（各スキル1問・基礎ができていれば標準）。テスト前日は「総仕上げ」（範囲を1問ずつ、仕上がりの低い順）。そのほかの日は、必要度（△3・？2.5・○2〜1.5・◎0.5）に比例して日数を割り当て、前提に近いスキルから並べる。1日2スキルまで
- **今日の学習**：今日の予定スキルを中心に、範囲の中だけで組み立てる（範囲外は「テスト範囲外」として除外）。「テストに出る形で」のパートは、基礎ができていれば標準以上。「なぜ今日はこれ？」はテストまでの日数・仕上がり・明日の予定を伝える
- **計画は毎日作り直す**：その日までの結果で仕上がりが変われば、残りの日の割り当ても変わる
- **テスト当日**は「落ち着いてがんばろう」、**終わったら**「テストおつかれさま」→ いつもの勉強にもどる
- **保存**：`profile.test_prep`（test_date・range_skills・active）。範囲チェックは `compass_check_history[].kind = "range_check"`
- **確認用**：`?debug=test` … 入力・仕上がりと必要度・残り日数の計画と割り当て・今日の学習・範囲外として除外したスキル。「テストを7日後に設定」ボタンあり

## 保護者向け画面（学習のようす）

子ども向けと同じデータを使い、見せ方だけを変える（子ども向け＝今日なにをするか、保護者向け＝なぜそれをやっているか）。ホーム下部の「保護者の方へ：学習のようすを見る」から開く。

- **今週のひとこと**：「今週は○○の理解が安定してきました。次は△△を中心に進めます。」（成長・現在地・次の方針だけ）
- **今週の学習**：この7日間に学習した日数・「学習の目安」（実測ではなく、完了した今日の学習の予定時間＋チェック1問1分）・いまの単元
- **最近できるようになったこと**：7日前の skill_state（その時点までの履歴から計算し直したもの）と比べて、段階が上がった／新しいレベルができたスキル。確認していたところから伸びた単元のスキルを先頭に、最大3つ（ほかは名前だけ）
- **いま確認しているところ**：今日の学習の中心スキルと、その理由（原因さがしで戻った場合は「○○そのものではなく、その前の△△を確認しています」）
- **つまずきの可能性**：原因さがしの結論（14日以内・まだ解決していないもの）と、記録上の不安定さ（14日で2回以上の×があるときだけ）。「〜の可能性があります」と伝え、断定しない
- **Study Compass の予定**：今日の学習の流れ・テストがあれば残り日数・次のコンパスチェックの目安
- **単元の地図**：スキルごとに ◎○↗△ とことば（点数や数値は出さない）
- **出さないもの**：点数・正誤の数・正答率・順位・他の子との比較・毎回の間違い
- **確認用**：`?debug=parent` … 使ったデータ・学習時間の計算・skill_state・成長の判定（7日前→いま）・つまずき候補と根拠（14日の×の数・解決済みかどうか）・次の予定

## 公開方法

静的ファイルだけなので、このフォルダをそのまま置けば公開できます。

- GitHub Pages：リポジトリにこのフォルダの中身を置き、Settings → Pages で main ブランチのルートを公開
- Netlify Drop：https://app.netlify.com/drop にこのフォルダをドラッグ
- Cloudflare Pages：`npx wrangler pages deploy .`

## デモ手順（おすすめ）

1. 「コンパスチェックをはじめる」→「現在地をチェックする」
2. Q1 `-2`、Q2 `6`、Q3 `7` と答える
3. Q4・Q5 は「わからない」を押す
4. 追加確認が2問だけ出る（原因確認：増加量、傾き・切片）
5. 増加量は x `3`・y `5`（あえて違う答え）、傾き・切片は `-3`・`4`
6. 現在地：座標・比例・代入＝できている／変化の割合＝もう少し／グラフ・式＝確認中
7. 「今日の学習を作る」→ 増加量 → 変化の割合 → 一次関数に再挑戦
8. 振り返りで気持ちを選ぶと記録される

右上の「はじめから」でいつでもやり直せます。
